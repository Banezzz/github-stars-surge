Reports API

New visitors cannot scrape every past trending board, and a repo name often hides what the project actually does. This API returns stored snapshots so an agent can pull the catalog, then read each repo's name, description, and url.

Base URL

{{ base_url }} · authentication: none · JSON catalog · OpenAPI

curl {{ base_url }}/api/v1/overview
curl "{{ base_url }}/api/v1/search?q=video+generation&limit=50"
curl {{ base_url }}/api/v1/snapshots/weekly
curl "{{ base_url }}/api/v1/repos?fields=card&limit=1000"

What every repo object contains

These three fields are always first. Use the description; do not guess from the name.

FieldMeaning
nameowner/repo
descriptionGitHub about text captured with the snapshot
urlCanonical GitHub link
{
  "name": "Wan-Video/Wan2.2",
  "description": "Wan: Open and Advanced Large-Scale Video Generative Models",
  "url": "https://github.com/Wan-Video/Wan2.2"
}

Pass fields=card to return only those three fields.

Time-segmented boards

List stored periods, then fetch one daily / weekly / monthly board.

GET {{ base_url }}/api/v1/periods?range=weekly
GET {{ base_url }}/api/v1/snapshots/weekly
GET {{ base_url }}/api/v1/snapshots/weekly/2026-W35
GET {{ base_url }}/api/v1/snapshots/monthly/2026-08

All repos and keyword search

Aggregated unique repositories across history. Keyword search matches all tokens against name, description, and language.

GET {{ base_url }}/api/v1/repos?limit=200
GET {{ base_url }}/api/v1/repos?min_stars=5000&sort=peak_stars
GET {{ base_url }}/api/v1/search?q=video+generation&limit=100
GET {{ base_url }}/api/v1/repos/Wan-Video/Wan2.2
